# A Moment (一刻) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn ArtDex "collect once" into "capture a moment any number of times" — the earliest capture of an artwork is the 初遇 (first encounter), later ones are 重逢 (reunions) — laying the data foundation for the polaroid-develop capture ritual and the per-artwork postmark stack.

**Architecture:** Keep the existing DynamoDB `(user_id, artwork_id)` item key untouched. Instead of one overwriting record per artwork, each item carries a `moments` **list** that we append to with an atomic `UpdateCommand` (`list_append`). 初遇/重逢 is *derived* (earliest `capturedAt`), never stored as mutable state. The frontend store exposes the moments while keeping the existing `collected` map shape derived, so current screens (map, dex, achievements, profile) keep working with no change.

**Tech Stack:** Next.js 15 (App Router), React 19, TypeScript, `@aws-sdk/lib-dynamodb`, vitest (already configured; project currently has no app tests — this plan adds the first).

**Spec:** [docs/superpowers/specs/2026-06-15-a-moment-design.md](../specs/2026-06-15-a-moment-design.md)

## Phasing

This feature is large; it is split into three phases that each ship working, testable software:

- **Phase 1 — Moments data model (THIS PLAN, detailed below).** Multi-capture + 初遇/重逢 derivation across domain / DynamoDB / API / store. No new ritual UI yet; capturing the same artwork twice simply records two moments. Ships invisibly-correct foundation.
- **Phase 2 — Capture ritual (roadmap below).** Recognize → seal (press-and-hold) → 10–20s polaroid develop. Detailed in its own plan after Phase 1 lands.
- **Phase 3 — Artifact UI (roadmap below).** Per-artwork postmark stack: 初遇 gold-rimmed on top, 重逢 timeline. Detailed in its own plan after Phase 2 lands.

Each phase is its own `writing-plans` → execution cycle. Do not start Phase 2 until Phase 1 is merged and verified.

```ts
// Pure helpers for "moments" — a user can capture the same artwork many times.
// The earliest capture of an artwork is the 初遇 (first encounter); later ones are
// 重逢 (reunions). Kind is always DERIVED from capturedAt, never stored as state.

export interface Moment {
  capturedAt: string;        // ISO timestamp, e.g. "2026-06-15T10:30:00.000Z"
  museumId: string;          // museum the capture happened in
  exhibitionLabel?: string;  // snapshot label, e.g. "The Louvre, Paris"
  photo?: string;            // keepsake photo (the with-it / selfie shot)
  note?: string;
}

export type MomentKind = "first" | "reunion";

/** Moments ordered oldest-first (ascending capturedAt). Does not mutate input. */
export function sortMoments(moments: Moment[]): Moment[] {
  return [...moments].sort((a, b) => a.capturedAt.localeCompare(b.capturedAt));
}

/** The earliest moment for an artwork — the 初遇. undefined when there are none. */
export function firstMoment(moments: Moment[]): Moment | undefined {
  return sortMoments(moments)[0];
}

/** "first" only for the single earliest capture; "reunion" for every later one. */
export function kindOf(moments: Moment[], target: Moment): MomentKind {
  const first = firstMoment(moments);
  return first && first.capturedAt === target.capturedAt ? "first" : "reunion";
}
```

```ts
/**
 * Append one moment to a (user, artwork) record, creating the item on first capture.
 * Atomic via list_append — concurrent captures both land. Returns { isFirst }:
 * isFirst is true when this capture is the artwork's 初遇 (the list now has one entry).
 */
export async function appendMoment(
  userId: string,
  artworkId: string,
  moment: Moment,
): Promise<{ isFirst: boolean }> {
  const res = await ddb().send(
    new UpdateCommand({
      TableName: TABLES.collections,
      Key: { user_id: userId, artwork_id: artworkId },
      UpdateExpression:
        "SET moments = list_append(if_not_exists(moments, :empty), :one), " +
        "collected_at = if_not_exists(collected_at, :ts), " +
        "museum_id = if_not_exists(museum_id, :mid)",
      ExpressionAttributeValues: {
        ":empty": [] as Moment[],
        ":one": [moment],
        ":ts": moment.capturedAt,
        ":mid": moment.museumId,
      },
      ReturnValues: "ALL_NEW",
    }),
  );
  const moments = (res.Attributes?.moments as Moment[]) ?? [];
  return { isFirst: moments.length <= 1 };
}
```

## Notes / Decisions carried from the spec

- No decay, no gaze-timer, no rarity-throttled develop, no GPS geofence, no QR (YAGNI — see spec §7).
- Verification is light: live-capture only, optional location stamp. Identity comes from the recognize step, not from the (possibly occluded) keepsake photo.
- 初遇/重逢 is always derived from `capturedAt`, never stored — avoids a mutable "isFirst" flag drifting out of sync.
